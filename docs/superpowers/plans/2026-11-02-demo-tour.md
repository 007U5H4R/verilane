# Demo Tour Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A top-bar **Demo** button (plus a `?tour=1` cold link) that resets the demo data after a confirm, then walks a viewer through 8 spotlighted steps, each with a pitch line. The viewer performs every action.

**Architecture:**
- A tiny static `tourStore` holds `{active, step}`. It is a `useSyncExternalStore` over sessionStorage with a memory fallback. The Demo button, the ShellGate bypass and a `TourGate` in AppShell all read it.
- `TourGate` lazy-loads `TourHost` with `next/dynamic` only while the tour is active, copying the `AutopilotGate` pattern.
- `TourHost` contains the confirm dialog, the spotlight ring and the callout.
- Step content and completion rules live in a pure `steps.ts`. That file maps a Dexie-derived `TourSnapshot` to the current stage, so the step logic can be unit-tested without a DOM.

**Tech Stack:**
- Next.js 16.4.3: read `node_modules/next/dist/docs/` before touching routing or search params.
- React 19, Dexie with `useLiveQuery`, Tailwind tokens.
- Vitest (`unit` project, fake-indexeddb) and Playwright (`chromium-light`, `chromium-dark`).

**Spec:** `docs/superpowers/specs/2026-11-02-demo-tour-design.md` (approved 2026-11-02). Ticket: **TASK-44**.

## Global Constraints

- **Branch:** create a fresh worktree `.claude/worktrees/task-44-demo-tour` on a new branch `task/44-demo-tour`, cut from `task/38-emerald-redesign`. Merge `task/41-auto-send` into it first.
  - Copy the spec, this plan and the TASK-44 ticket file in from the main checkout, and commit them.
  - Never touch the main checkout's uncommitted edits.
- **Guided prompts only.** The tour never clicks, types or navigates for the viewer. The single exception is the confirmed reset and the redirect to `/queue`.
- **The reset needs consent.** It happens only after "Start the demo? This resets the demo data to a fresh start." → **Start demo**. **Cancel** exits the tour and leaves the data untouched.
- **Known start state on confirm:**
  - `resetDemo(db)`;
  - the role is Analyst;
  - autopilot is off with the default cap (`paise(5_000_000)`);
  - the app is on `/queue` at step 1.
- **The pitch copy is verbatim from the spec**, steps 1–8. Autopilot is always framed as "you set the rules".
- **The callout:**
  - It is a non-modal `role="dialog"` with a labelled heading and the text "Step N of 8".
  - Focus moves to it on every step change.
  - Esc and Skip tour both exit.
  - Next is always enabled. Back only moves the explanation and never undoes data.
- **Prefers-reduced-motion:** no transitions on the ring or the callout.
- **Mobile:** at ≤767px the callout is a bottom sheet. There is no horizontal scroll at 375 or 768px. A target that is in the sidebar resolves to the **More** button.
- **Bundle:** the Demo button and `tourStore` are the only static additions. Everything else is lazy. Record route-budget before and after; no route may grow by more than 1 KB gzip.
- **Commits:** imperative mood, each tagged `TASK-44`, with no AI attribution. Commit only once the task's gate is green.
- **Disk:** scratch files and screenshots go under `/Volumes/E Drive/Dev/.scratch/verilane/`.

## Review Focus

1. **Refreshing mid-tour** (sessionStorage survives the reload) must resume at the same step on the same page, not restart and not reset the data. *Test: Task 3 `tourStore` restore and Task 7 e2e reload.*
2. **The target hasn't rendered yet.** Dexie loads late and lazy panels mount after the step does, so the ring must appear once the element mounts and must not throw or point at nothing. *Test: Task 5 `findTarget` retry and Task 7 asserting the ring is visible after navigation.*
3. **The viewer is on the wrong page or role for a step,** for example on `/drafts` at step 3. The callout must name where to go and ring the nav link, or **More** on mobile. *Test: Task 2 `currentStage` returns the `navHint` stage and Task 7 checks it at 375px.*
4. **The Demo button is pressed while a tour is already running.** It must re-confirm and restart, not stack a second host. *Test: Task 6.*
5. **sessionStorage throws** (private mode or blocked storage). The tour must still run, in memory. *Test: Task 3 with a throwing storage stub.*

### Task 2: Pure step definitions and stage resolution

**Files:**
- Create: `src/components/tour/steps.ts`
- Create: `src/components/tour/steps.test.ts`

**Interfaces:**
- Consumes: `TOUR_INVOICES` (Task 1).
- Produces:

```ts
export type TourSnapshot = {
  role: "analyst" | "manager";
  autopilotEnabled: boolean;
  draftA: { status: DraftStatus; sent_by?: "human" | "copilot" } | null;
  draftB: { status: DraftStatus; sent_by?: "human" | "copilot" } | null;
};
export type TourStage = {
  prompt: string;           // the "👉 do this" line
  target: string;           // CSS selector to ring
  route: string;            // pathname the target lives on
  navHint?: { label: string; target: string; mobileTarget: string };
};
export type TourStep = {
  id: string; title: string; pitch: string; // pitch verbatim from spec
  stages: (TourStage & { done: (s: TourSnapshot) => boolean })[];
  completes: "next" | ((s: TourSnapshot) => boolean);
};
export const TOUR_STEPS: readonly TourStep[];  // length 8
export function currentStage(step: TourStep, s: TourSnapshot, pathname: string, substage: number):
  { kind: "stage"; stage: TourStage } | { kind: "wrong-page"; stage: TourStage } ;
export function isStepComplete(step: TourStep, s: TourSnapshot): boolean;
```

`currentStage` starts at index `substage` and picks the first stage from there whose `done(s)` is false. If every stage is done, it picks the last one. When `pathname` doesn't match the stage's route, it returns `wrong-page`; `/invoices/INV-A` matches `route: "/invoices/INV-A"` exactly.

The stages:

| Step | Stages, with targets |
|---|---|
| 1 | `[data-tour=queue-list]` |
| 2 | First the INV-D row (`[data-tour=queue-row-INV-D]`, done after Next). Then "Open the top invoice", targeting `a[href="/invoices/INV-A"]`. |
| 3 | `[data-testid=priority-reason]`. The prompt says to click "Generate draft". |
| 4 | `[data-testid=checks-summary]`, then `[data-testid=primary-action]`. |
| 5 | The role switcher (`[data-tour=role-switcher]`), done when the role is manager. Then the primary action on `/invoices/INV-A`. |
| 6 | `[data-testid=autopilot-control]` on `/settings`. |
| 7 | The role switcher, done when the role is analyst. Then Generate, then Submit on `/invoices/INV-B`. |
| 8 | `[data-tour=audit-table]` on `/audit`. |

Step 2's look-only first stage is handled by the host advancing a sub-index on Next. Keep a `substage` number in the store state (Task 3) for look-only stages, and give those stages `done: () => false`.

### Task 3: Tour store, snapshot hook and the confirmed start

**Files:**
- Create: `src/components/tour/tourStore.ts`, a static import kept tiny. It must not import Dexie or the steps.
- Create: `src/components/tour/startTour.ts`
- Create: `src/components/tour/useTourSnapshot.ts`
- Test: `src/components/tour/tourStore.test.ts`, `src/components/tour/startTour.test.ts`

**Interfaces:**
- Produces (`tourStore.ts`):

```ts
export type TourState = { phase: "idle" | "confirm" | "running" | "finished"; step: number; substage: number };
export function getTour(): TourState;
export function setTour(next: TourState): void;      // writes sessionStorage "verilane-tour" in try/catch, notifies
export function subscribeTour(cb: () => void): () => void;
export function useTour(): TourState;                // useSyncExternalStore; server snapshot = idle
export function requestTour(): void;                 // → {phase:"confirm", step:0, substage:0}
export function exitTour(): void;                    // → idle
export function createTourStore(storage: Pick<Storage,"getItem"|"setItem"> | null): {...same API} // for tests
```

- Produces (`startTour.ts`): `confirmStartTour(db: VerilaneDb, fetcher?: typeof fetch): Promise<void>`. It runs `resetDemo(db, fetcher)`. Then, if `currentRole` isn't analyst, it executes `switch_role {role:"analyst"}`. Then it writes the autopilot policy as off with the default cap, skipping the write when it is already equal, because the command rejects an unchanged policy with /already/. Finally it calls `setTour({phase:"running", step:0, substage:0})`. Navigating to `/queue` is the caller's job, via `router.push`.
- Produces (`useTourSnapshot.ts`): `useTourSnapshot(): TourSnapshot | undefined`. It is built from `useRole()`, `useAutopilotPolicy()` and `useInvoiceDraft(TOUR_INVOICES.a/b)` in `src/store/hooks.ts`.

Note: `set_autopilot` is Manager-only. Writing "off" as an Analyst throws. Since the reset already restores the default, `confirmStartTour` reads the policy and writes nothing when it is already `{enabled:false, max_amount_paise:5_000_000}`. The test pins this.

### Task 5: TourHost: confirm dialog, spotlight and callout (lazy)

**Interfaces:**
- Consumes: Tasks 2 and 3, `useRouter`/`usePathname` from `next/navigation`, and `DbContext`.
- Produces: `findTarget(selector: string, mobileFallback?: string): HTMLElement | null`. It returns the first visible match (non-zero rect). When the match is inside a hidden sidebar and a fallback is given, it returns the fallback. It is used by Spotlight on each animation frame or `ResizeObserver` tick, until found.

Behaviour:
- **Confirm phase:** a `role="alertdialog"` with the spec copy. **Start demo** → `confirmStartTour(db)` then `router.push("/queue")`. **Cancel** → `exitTour()`. While the reset runs, disable both buttons and show "Resetting…".
- **Running phase:**
  - Find the target, `scrollIntoView({block:"center"})` it, and draw the ring.
  - The ring is a fixed box sized to the target's rect, using `box-shadow: 0 0 0 9999px` dim plus a 3px solid ring and a 2px dashed outer outline as the non-colour cue, with `pointer-events:none`.
  - Re-measure on scroll, resize and `ResizeObserver`.
  - Watch `useTourSnapshot()`. When `isStepComplete` turns true, advance (`step+1, substage 0`).
  - On the wrong page, show the `navHint` and ring its target (`mobileTarget` at ≤767px).
- **The callout:**
  - It contains: "Step N of 8 · {title}", the pitch, the 👉 prompt, Skip tour, Back and Next (Finish on step 8).
  - It is a floating card beside the target at ≥768px, and a fixed bottom sheet at ≤767px with `max-width:100vw`.
  - It focuses its heading when the step or substage changes.
  - Esc → `exitTour()`.
- **Finished phase:** "You've seen Verilane." with **Restart demo** (`requestTour()`) and **Explore on my own** (`exitTour()`).
- Respect `motion-reduce:` on all transitions.
